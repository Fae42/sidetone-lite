# Sidetone Lite

[English](README.en.md) | 简体中文

一个轻量、原生、低占用的 Windows 麦克风耳返工具。选择麦克风，即可在耳机中实时听到自己的声音。

![Sidetone Lite 主界面](docs/images/window.png)

## 适合这些场景

- **打游戏和队友沟通**：枪声、键盘声、队友声混在一起时，也能听清自己是否说清楚了，不用靠吼，避免把“喊麦”当沟通。
- **直播或录制**：开播前先听自己的音量和底噪，及时发现声音太小、爆音或设备接错，少录废片。
- **线上会议和网课**：开麦前确认设备正确、声音正常，少一点“喂，能听到吗？”
- **配音、朗读和唱歌练习**：实时听自己的呼吸、节奏和音量变化，比事后回放更及时。
- **多设备桌面**：在 USB 麦克风、耳机麦克风和虚拟设备之间，快速确认当前输入是否正确。

## 功能

- 输入设备可选，输出跟随 Windows 默认设备
- WASAPI 共享音频，优先尝试驱动支持的最低周期，失败时自动回退
- 音量 0–800% 可调，带平滑增益与软限幅
- 可开关的轻量噪声门，默认关闭
- 记住上次成功使用的麦克风
- 设备断开、默认输出变化时给出明确提示
- 单文件原生 exe，约 284 KiB，无浏览器或后台服务

## 下载

从 [Releases](https://github.com/Fae42/sidetone-lite/releases/latest) 下载 `SidetoneLite.exe`，直接运行即可，无需安装。

**请使用耳机，尤其是有线耳机。** 音箱外放可能产生啸叫；蓝牙耳机本身也会增加延迟。

## 从源码构建

要求：

- Windows 10/11 x64
- MinGW-w64 g++（支持 C++20）
- Windows PowerShell 5.1 或 PowerShell 7+

如果 PATH 中没有 `g++`，脚本会尝试使用项目内的 `tools/w64devkit/bin/g++.exe`。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./build.ps1
```

输出：`dist/Jianting.exe`。

## 测试

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./test.ps1
```

测试在控制台中构建并运行，不打开监听窗口、不访问真实麦克风。覆盖：

- INI 配置读写与空值
- 高倍率重采样和跨包边界
- 环形缓冲溢出与静音填充
- 增益限幅
- 噪声门状态转换

CI 在每次 push 和 pull request 时执行同样的构建与测试，并上传 Windows x64 可执行文件。

## 小、快、省，靠实测说话

一个约 284 KiB 的原生 exe，没有 Electron、浏览器、后台服务或大型音频框架。事件驱动音频线程只在需要时工作，不为“功能丰富”付出额外资源。

| 实测指标 | 结果 | 说明 |
| --- | ---: | --- |
| exe 体积 | 约 284 KiB | 单文件、免安装 |
| 20 分钟监听平均 CPU | 约 0.35% 单核 | 长时间运行依然轻量 |
| 工作集 / 私有内存 | 约 31 MiB / 7.7 MiB | 无大型运行时负担 |
| 结束时的线程 / 句柄 | 6 / 330 | 无持续增长 |
| 60 秒低周期平均 CPU | 约 0.42% 单核 | 低延迟不等于高占用 |

测试环境：HyperX Cloud III、10 ms 内部缓冲、100% 增益、WASAPI 共享模式。数据来自开发过程中的本机抽测，仅作量级参考，不是跨硬件基准或性能保证。

## 使用说明与限制

- 启动后选择麦克风，点击“开始监听”；运行时先停止才能切换输入。
- 100% 是原始增益；超过 100% 会同时放大底噪，过高增益可能产生压缩感。
- 实际端到端延迟还取决于 Windows 音频引擎、驱动和耳机，不等于界面显示的周期。
- 低周期是否生效由输出驱动决定；状态栏显示实际接受的周期。
- `Jianting.ini` 保存在 exe 旁，仅记录设备 ID。目录不可写时只是不记忆，不影响监听。
- 不支持录音、持续 AI 降噪、虚拟声卡、独占模式或多输出路由。

## 隐私

音频只在本地内存中处理，不联网、不写入录音文件，也不设置开机自启动。配置文件只包含上次成功使用的麦克风 ID。
