# 监听：麦克风实时耳返设计

## 目的

为 Windows 游戏场景制作一个轻量麦克风耳返工具，让用户能通过耳机实时听到自己的声音，同时尽量避免额外延迟、资源占用和音频设备冲突。

## 已确认需求

- Windows 10/11 x64 原生小 exe。
- 输入麦克风可下拉选择。
- 输出跟随 Windows 默认多媒体输出设备。
- 监听音量 0–800% 可调，100% 表示原始增益；超过 100% 时提供额外增益并平滑限幅，高增益可能增加底噪与压缩感。
- 明确的开始/停止控制。
- 可开关的轻量噪声门，默认关闭；不做持续降噪。
- 低 CPU、低内存占用，不抢占游戏使用的音频设备。
- exe 体积尽量小；使用原生代码、裁剪未使用部分，不使用压缩壳，且不牺牲音频稳定性。
- 深色、紧凑、轻量极简但有质感的界面。
- 不联网、不录音到磁盘、不做开机自启、不安装后台服务，退出后不留驻留进程。

## 非目标与避免事项

- 不做录音、变声、混音、持续 AI 降噪、虚拟声卡或多输出路由。
- 不使用 Electron、浏览器或大型界面框架。
- 不为了极限缓冲而牺牲稳定性；爆音和持续卡顿属于失败。
- 不承诺蓝牙音频或所有驱动都能达到相同的绝对延迟。
- 不用夸张动画、大标题、大卡片或复杂控制台破坏轻量感。

## 方案取舍

- **原生 C++ + Win32 + WASAPI 共享模式：已选择。** 体积小，音频设备行为可控，不会独占设备。
- WASAPI 独占模式：可能进一步降低部分链路延迟，但会与游戏或语音软件争用设备，排除。
- 网页版：开发快，但延迟、输出路由及浏览器音频策略不够可控，排除。
- OBS/Voicemeeter：可作为现成替代，但为此单一需求配置和运行成本偏高，排除。
- Rust/Qt 等界面方案：可以实现，但对这种小窗口带来不必要的依赖或体积，排除。

## 音频设计

使用事件驱动的 WASAPI 共享采集与渲染。优先通过 IAudioClient3 查询并初始化驱动允许的最低共享周期，失败时回退到普通共享模式；状态栏显示实际接受的周期。音频线程只执行必要的格式转换、重采样、音量与噪声门处理，不轮询等待。需要处理常见采样率、单声道/立体声差异以及独立输入输出时钟造成的缓慢漂移。内部目标缓冲为 5 ms 且至少覆盖一个实际音频周期，启动时先积累实际采集帧，欠载后重新预填；不请求独占模式。音量变化使用 5 ms 平滑，超过原始增益的输出通过软拐点限幅，避免直接削波。

噪声门只压低低于阈值的环境声，使用平滑进入与释放，避免硬切造成咔哒声。它不能消除说话期间的底噪，界面不把它宣传为持续降噪。

## 界面设计

单个固定尺寸深色小窗口，以设备下拉框、音量滑条和启停按钮为主体。噪声门是一个小开关，状态只显示运行、停止及必要错误。使用紧凑排版、细腻边框、统一间距和单一强调色，不加入无意义动画或虚假的性能数字。

设备断开或默认输出变化时不得静默失效；显示明确状态，并允许重新选择或重新开始。建议用户戴有线耳机，避免外放啸叫和蓝牙额外延迟。

## 验证与完成标准

- 能从干净项目目录编译出可运行的独立 exe。
- 能选择可用麦克风，开始、停止并恢复监听；音量与噪声门开关实时生效。
- 输入或输出设备变化有可见、可恢复的状态，不崩溃。
- 连续运行时没有持续增长的缓冲、明显周期性爆音或资源泄漏。
- 实测监听时 CPU 与内存；以游戏中几乎无感为目标，但不声称绝对零影响。
- 最终听感、底噪和延迟需要用户戴耳机在实际麦克风与输出设备上确认。

## 留给实现者的决定

默认周期、环形缓冲目标、噪声门阈值与释放时间可在上述目标内微调。本机没有现成 C++ 编译器，可使用项目内的便携 MinGW-w64 工具链构建；便携工具不是最终程序的运行依赖。
